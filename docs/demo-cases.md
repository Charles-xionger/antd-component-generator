# Prompt Web 目标案例与验收条件

目标案例用于四件事：产品演示、生成质量评估、浏览器 E2E 和 Agent 面试讲解。

所有案例必须能够从固定 Prompt 开始，在不手工改代码的情况下完成生成、修改、真实预览和发布。

## 案例 A：短剧分镜产能管理台（P0 黄金案例）

### 为什么优先

仓库已经存在 `test/fixtures/aigc-storyboard-productivity/`，覆盖人员、短剧项目、分镜任务、工时记录和统一产能统计。它同时包含看板、表格、筛选、状态修改和真实数据持久化，适合建立第一条稳定演示链路。

### 固定起始 Prompt

> 创建一个短剧分镜团队的产能管理应用。首页展示本周完成分镜数、投入工时、平均单镜耗时和延期任务数；下方显示七日产能趋势、成员产能排行和分镜任务表。任务支持按项目、负责人和状态筛选，可以新建任务、修改负责人、登记工时和标记完成。整体使用专业、克制的深色运营后台风格，并适配手机查看。

### 页面与数据

- 总览：四张统计卡、七日趋势图、成员排行、异常提醒。
- 分镜任务：搜索、筛选、分页、创建、编辑状态与负责人。
- 工时登记：选择任务、填写日期和时长、提交后更新统计。
- 数据实体：Member、Project、StoryboardTask、Worklog。

### 演示中的局部修改

> 把“延期任务数”改成最近七天趋势卡；超过三项时使用红色，并在卡片下显示环比。

### 验收条件

- 首屏在 1440px 下完整呈现统计卡、趋势图和任务表入口。
- 390px 下无横向滚动，统计卡改为纵向或双列排列。
- 新建任务后无需刷新即可出现在任务表中。
- 登记工时后，总工时和成员排行数据同步变化。
- 项目、负责人和状态筛选可以组合使用。
- 应用容器重启后业务数据仍然存在。
- 真实预览通过健康检查和既有 10 步 API acceptance 场景。
- 发布后 URL 在无登录窗口可以访问，重新发布时 URL 不变。

## 案例 B：销售客户跟进台账（P1）

### 固定起始 Prompt

> 创建一个销售客户跟进台账。首页展示客户总数、本月新增、待跟进和预计成交金额；包含销售漏斗和最近跟进记录。客户列表支持按负责人、阶段和更新时间筛选，可以新增客户、记录跟进内容、修改销售阶段和设置下次跟进日期。逾期跟进需要明显提醒。

### 页面与数据

- 销售总览：统计卡、销售漏斗、待办跟进。
- 客户列表：搜索、组合筛选、分页和阶段标签。
- 客户详情：基础信息、跟进时间线、下一步计划。
- 数据实体：Customer、Owner、FollowUp、Opportunity。

### 演示中的局部修改

> 选中销售漏斗，把它改成按负责人分组，并增加“只看本月预计成交”的开关。

### 验收条件

- 新增客户后统计卡和客户列表同步更新。
- 写入跟进记录后详情时间线立即出现新记录。
- 过期的下次跟进日期显示警告状态。
- 阶段筛选与负责人筛选可以组合并正确更新漏斗。
- 局部修改不能破坏客户新增和跟进记录流程。
- 发布版本与预览版本的核心数据流程一致。

## 案例 C：活动报名与签到管理（P1）

### 固定起始 Prompt

> 创建一个小型活动报名管理应用。运营人员可以创建活动、设置人数上限和报名截止时间；报名列表支持搜索、状态筛选、确认报名和现场签到。首页展示报名人数、确认人数、签到率和剩余名额，并用趋势图展示最近七天报名变化。

### 页面与数据

- 活动总览：活动信息、四张统计卡、报名趋势。
- 报名名单：搜索、筛选、确认、取消和签到。
- 活动设置：人数上限、截止时间和开放状态。
- 数据实体：Event、Registration、CheckIn。

### 演示中的局部修改

> 给剩余名额卡增加进度条；名额低于 20% 时显示橙色，满额时显示红色并隐藏报名按钮。

### 验收条件

- 报名人数达到上限后不能继续创建有效报名。
- 截止时间之后报名按钮不可用，并解释原因。
- 确认、取消和签到操作会正确更新统计卡。
- 同一报名不能重复签到。
- 手机端可完成搜索与签到主流程。
- 发布后可从另一浏览器完成报名或查看公开状态。

## 案例 D：从参考图生成数据看板（P2 视觉案例）

### 目标

验证图片输入、视觉语言提取、设计约束和局部修改能力。该案例不作为 P0 现场演示依赖项，避免视觉生成的不确定性影响主闭环。

### 输入

- 一张授权使用的后台看板参考图。
- 一段业务数据说明。
- 明确要求保留的信息层级、配色倾向和响应式行为。

### 验收条件

- 信息结构、密度和视觉层级与参考方向一致，但不复制第三方品牌。
- 生成结果使用统一 Design Token，不出现随意颜色和间距。
- 图表、空状态、加载状态和移动端均有完整表现。
- 用户选中区域修改时，其余布局与设计语言保持稳定。

## 黄金案例运行规则

### 固定输入

- 固定起始 Prompt。
- 固定模型与模型参数。
- 固定 seed 数据和图片资产。
- 固定 runtimeVersion、组件版本和验收脚本。

### 每次演示前

1. 运行环境检查。
2. 重置 DRAFT 演示数据。
3. 确认已有一个成功构建的回退 ArtifactVersion。
4. 执行 API 验收和浏览器主流程。
5. 在无登录窗口检查发布地址。

### 记录结果

- 首个可用预览耗时。
- 首次生成是否命中核心页面与数据模型。
- 达到目标页面所需修正轮数。
- 构建、验收与发布是否成功。
- 截图、Trace、Console 和 Network 证据。
- 失败原因以及是否能够自动或手动恢复。

只有案例 A 连续 10 次满足全部验收条件，才能作为正式现场演示版本。
